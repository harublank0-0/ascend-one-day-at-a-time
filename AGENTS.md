## Environment

- `.env` is the primary env file (gitignored; copy `.env.example`). `.env.test` overrides `SESSION_DRIVER=memory`, `DB_DATABASE=ascend_test` and `PORT=0`
- All other test env vars fall back to `.env`
- `APP_URL` in config/app.ts is derived from `env.get('APP_URL')` — set in `.env`
- `DB_CONNECTION=pg` in config, but `.env` has PG connection details; SQLite is commented out in `config/database.ts`
- Ensure PostgreSQL is running if using the DB (`pg` client); `better-sqlite3` is available for SQLite
- Run migrations with `node ace migration:make <name>` and `node ace migration:run`; first-time setup is `node ace migration:run` then `node ace db:seed`
- `database/schema.ts` is regenerated by `migration:run` (rules in `database/schema_rules.ts`, wired in `config/database.ts`): DATE columns are generated as plain `string`

## Monorepo / Package boundaries

- Single pnpm workspace (root is the only package)
- `app/` contains backend code (controllers, models, middleware, etc.)
- `inertia/` contains the React + Vite frontend (Inertia.js integration)
- `database/migrations/` — migration files; `database/schema.ts` is auto-generated from migrations
- `providers/api_provider.ts` — adds `ctx.serialize()` for consistent API responses
- `providers/` — custom service providers registered in `adonisrc.ts`
- `imports` in `package.json` map `#*` aliases to `./app/*, ./start/*, ./config/*`, etc.
- `#generated/*` maps to `./.adonisjs/server/*.js` — these are codegen outputs

## Key framework quirks

- `adonisrc.ts` `hooks.init` runs `indexEntities`, `indexPages`, and `generateRegistry()` — do not remove without codegen re-run
- `adonisrc.ts` `tests.suites` has unit/functional/browser with different timeouts (2s/30s/300s)
- `ctx.serialize(data)` from `api_provider.ts` wraps responses in `{ data: ... }` — use in API controllers
- `UserTransformer` at `app/transformers/user_transformer.ts` — use `UserTransformer.transform(auth.user)` in Inertia `share()`
- Inertia middleware at `app/middleware/inertia_middleware.ts` shares `user` and `errors` with all pages
- `allowScripts` in package.json includes `better-sqlite3`, `esbuild` — needed for native deps
- `useAsyncLocalStorage: false` in `config/app.ts` — ALS is disabled
- `allowMethodSpoofing: false` in `config/app.ts` — no `_method` spoofing
- `redirect.forwardQueryString: true` in `config/app.ts` — a redirect to a URL that should drop the query string (for example a bad `?date=`) needs `.withQs(false)` or it loops
- Redirects after `PUT`/`DELETE` from Inertia are sent as 303 automatically; tests should expect that
- Dates are `"YYYY-MM-DD"` strings end to end (`config/database.ts` makes the pg driver return DATE as text). Read `docs/adr/0001-time-and-timezone-handling.md` before touching anything date-related; helpers live in `app/services/calendar_dates.ts`
- Business rules live in `app/services/*`; controllers stay thin. Services take `now` so tests can place the clock either side of a user's local midnight
- Journal routes are addressed by date, never by id, and every query is scoped to the signed-in user. Keep it that way

## Testing quirks

- Test suites: `unit` (files matching `tests/unit/**/*.spec.{ts,js}`), `functional` (`tests/functional/**/`), `browser` (`tests/browser/**/`)
- `tests/bootstrap.ts` starts http server for functional/browser suites — do not remove `testUtils.httpServer().start()`
- Tests run against an isolated `ascend_test` database. `tests/bootstrap.ts` creates it if missing, migrates it, and refuses to run if `DB_DATABASE` does not end in `_test`
- `testUtils.db().truncate()` does not truncate when called: it returns the cleanup that truncates after the test. Return it from the setup hook (`group.each.setup(() => testUtils.db().truncate())`); awaiting it and dropping the result leaks data between tests
- Functional specs use `tests/helpers/http.ts` (`Session`: cookie jar, real CSRF token, Inertia headers) and `tests/helpers/clock.ts` (`freezeClock`)
- `forceExit: false` in `adonisrc.ts` tests config — a failing run can hang instead of exiting; add `--force-exit` while iterating (a passing `pnpm test` exits by itself)
- Run one spec with `node ace test functional --files=<name>`

## Lint / Type / Format order

Always run in this order: `lint` -> `typecheck` -> `test` (then `pnpm build` before calling something done)

- `pnpm typecheck` also checks the Inertia tsconfig; a failure here blocks test. `@inertiajs/core` is a direct devDependency because `inertia/types.ts` augments it
- Filenames are snake_case (`@unicorn/filename-case`), including components, and `(await x).y` is banned (`@unicorn/no-await-expression-member`): assign the awaited value first
- `pnpm add` rewrites `pnpm-lock.yaml` in compact form; run `npx prettier --write pnpm-lock.yaml` afterwards to keep the diff small
- `prettier` ignores `.adonisjs`, `node_modules`, `build` (per `.prettierignore`)
- `lint-staged` runs on pre-commit (`pnpm exec lint-staged`); it runs `lint` and `format` on staged files

## Infra / Docker

- `docker-compose.yml` defines services (check for DB, Redis, app)
- Redis is configured in `.env` (`REDIS_CONNECTION=local`, host/port)
- If running locally: ensure Postgres (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_DATABASE`) and Redis are accessible
- Another project may already hold port 5432, so this one runs on 5434. Compose reads `.env`: set `POSTGRES_USER=ascend`, `POSTGRES_PASSWORD=ascend`, `POSTGRES_DB=ascend`, `POSTGRES_PORT=5434` there and keep `DB_PORT=5434` in sync. Then plain `podman-compose up -d postgres` (or `podman start ascend-postgres`) is enough
- Without those values, `podman-compose` 1.3 passes the literal text `${POSTGRES_USER:-ascend}` as the Postgres user (it does not expand defaults inside `environment:`), which breaks first-time initialisation with "invalid character in extension owner", and it maps the default port 5432
